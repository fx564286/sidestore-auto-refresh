# Scarlet Crystal P78 — P76 signed JIT-Less signature postcheck regression repair

## Measured P76 source + real iPhone evidence
- Signed build 3.8.76 SourceCommit `d27ea1605940`, session `5def4d0b`, 2026-11-15 15:46–15:57 UTC. Four guest launch attempts failed `signing_reason=certificate_invalid`, and native LCUtils.validateJITLessSetup reported `signature_postcheck_invalid` (`NSError code2`) independently. `certificate_preflight certificate_present=true password_present=true team_match=match` proves only P12 exists/team metadata matches, not that codesign succeeds.
- Actual SideStore managed apps later returned count1 ready. This does NOT prove that SideStore's separate signing P12 is valid for guest LiveContainer, nor that its Keychain is visible to host; check candidate and real JIT-Less signing separately.
- Exact source failure: `ScarletIntegratedHostView.bridgeExistingSideStoreCertificateIfSafe()` exits at `guard LCUtils.certificateData() == nil else { return }`. An invalid-but-present LC P12 is therefore never replaced with a real tested alternate same-host-Team SideStore certificate. Existing UI just presents a warning; repeated launches keep failing. This is a distinct problem from P76 Dynamic Island mixed-owner controls and from pairing RSD transport.

## Executable P78 solution — deterministic and reversible
1. Keep missing-certificate bridge, native installer and P75 selected-Team gates unchanged. ONLY after `LCUtils.validateJITLessSetup` reports the concrete kernel signature-postcheck-invalid outcome (not mere missing cert, password/team match, or generic zsign string), start a one-at-a-time, native signer recovery trial.
2. Read existing SideStore `signingCertificate` + password from existing Keychain services. Require candidate differs from current LC P12, PKCS#12 team derived using `getCertTeamId` equals the *actually Apple signed HOST entitlement team*, not whichever Apple account B is currently selected. No revocation, signing request, new cert issuance, role/account change or saved pairing mutation.
3. Before swapping the live signing candidate, atomically write crash-recovery keys to the same already-entitled LC AppGroup UserDefaults containing its original P12: old data/password/original update timestamp + trial SHA256 + pending flag. If persistence fails, abort without changing the live signer. During trial block guest launches; `onAppear` restores an interrupted candidate before first guest bootstrap. If user independently selected a different P12, compare SHA256 and keep their choice rather than reverting it.
4. Temporarily apply alternate to the existing `LCCertificateData`/`LCCertificatePassword` keys, read back, and run the pinned native `LCUtils.validateJITLessSetup` on a temporary signed dylib. Only if this *real signature postcheck* succeeds keep the candidate and remove backup. On failure undo exactly those LC keys and restore original; leave SideStore credentials untouched. Never export P12, password, UDID, email, token or Team ID to JSONL. Event logs only `trial_started`, `verified`, `rolled_back`, `candidate_unavailable`, or crash-safe restoration.
5. On native verified success, clear the one transient signing-recovery flag so the next guest launch actually uses the proven certificate. No additional buttons, settings paragraphs, duplicate automatic label, color changes, virtual windows, app uninstall, or profiles revoked.

## Device acceptance test
- Starting with the P76 signed device's invalid LC signer, `signer_recovery_trial_started` must appear only after actual `jitless_probe_failure_classified(signature_postcheck_invalid)`. Followed by either (A) `signer_recovery_verified(kernel_signature_postcheck_passed)` and a successful launch of the previously blocked guest, or (B) `signer_recovery_rolled_back(original_p12_preserved)` and original readback, or (C) `signer_recovery_candidate_unavailable` without modifying existing credentials.
- Force-kill/restart during trial must restore originals before guest launch; concurrently imported third-party P12 must not be overwritten. Signed host account A/B Team separation, guest data and all saved certs preserved.
- Dynamic Island P77 severity correction and RSD manual-refresh transport are separate. Python static tests and macOS Xcode CI never prove that a user's particular P12 is valid on their iPhone.
